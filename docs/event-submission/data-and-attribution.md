# Data, attribution, and licensing record

## Data in the current repository

| Material | Provenance | Use and limit |
| --- | --- | --- |
| Synthetic holdings and market observations | Deterministically generated by `backend/app/demo.py`; companies and funds are fictional | Local UI and pipeline demonstration only; no real-world accuracy claim |
| Example CSV templates | `frontend/public/templates/`; example fields and rows | Schema illustration, not an official disclosure |
| User-imported holdings/market CSVs | Supplied by the operator, with source URL and report/publication dates recorded | Import does not independently verify the URL, source license, or permission |
| Company events | User-supplied source URL, publication time, and excerpt | Optional extraction must match identifiers/provenance and source text |

The root README links to AMFI disclosure pages as discovery references. No AMFI/AMC, NSE/BSE, market-feed, or news dataset is bundled here. Before a real-data submission, record each original file's URL, publisher, publication date, retrieval date, license or written permission, normalization steps, and any exclusions. A public page is not automatically an open data license.

## Code and UI attribution

- Backend and frontend dependency names and versions are recorded in `backend/requirements.txt` and `frontend/package-lock.json`; their upstream licenses govern those packages.
- The dither background and some interface component code were supplied by the project owner during development. Their original upstream source and redistribution permission need owner confirmation before a public event submission; do not imply they were all authored during the sprint.
- Earlier design references and component research are recorded in [the implementation audit](../implementation-audit.md).
- This repository has no `LICENSE` file. The owner should choose and add one if they intend to grant reuse rights. The handbook mentions MIT or Apache-2.0 as common options (p. 11); it does not choose a license for this project.

## Limits to state in every review

The candidate target is a future **disclosed position**, not a trade. The ranker uses uncalibrated scores. User-supplied completeness and dates affect labels. Synthetic evaluation establishes software behavior only. Real predictive performance, customer value, and data rights still require verification.
